# jamfpro_smart_computer_group_v3 (Resource)

Manages a Jamf Pro smart computer group using `/api/v3/computer-groups/smart-groups` (Jamf Pro 11.28.0 or later). Known criterion validation defects use a targeted Classic API fallback. Names are case-insensitively unique across smart, static, and Platform computer groups.

## API behavior

- Criteria are ordered. Set each `priority` to its zero-based block position; parentheses must be balanced.
- Known v3 criterion/operator validation refusals trigger one complete Classic write containing name, site, and all criteria. A warning identifies this workaround.
- Classic writes preserve the existing description. A changed description is patched separately using the group's Platform identifier, after the group write becomes readable. Setting or defaulting `description` to an empty string clears it.
- Removing every criteria block clears the criteria. Removing `site_id` assigns the group to None (`-1`).
- Names are case-insensitively unique across smart, static, and Platform computer groups. Use names without surrounding whitespace, because Classic writes trim it.
- For directory-service group criteria, use a base64-encoded JSON `value` containing `uuid` and `serverId`, as required by Jamf Pro.
- A group deleted outside Terraform is removed from state during refresh so Terraform can recreate it.

## Example Usage

```terraform
# Requires Jamf Pro 11.28.0 or later.
resource "jamfpro_smart_computer_group_v3" "example" {
  name        = "Managed Macs running macOS 26"
  description = "Computers matching both criteria."
  site_id     = "-1" # None

  criteria {
    name        = "Managed"
    priority    = 0
    search_type = "is"
    value       = "Managed"
  }

  criteria {
    name        = "Operating System Version"
    priority    = 1
    and_or      = "and"
    search_type = "like"
    value       = "26."
  }

  timeouts = {
    create = "3m"
    read   = "3m"
    update = "3m"
    delete = "3m"
  }
}

# Import using the numeric Jamf Pro group ID, not its Platform UUID:
# terraform import jamfpro_smart_computer_group_v3.example 123
```

## Import

Import using the numeric Jamf Pro group ID:

```shell
terraform import jamfpro_smart_computer_group_v3.example 123
```

When moving an existing group from another resource type, back up state, remove its old state association without destroying the group, and import the same numeric ID into this resource. Manage the group through one resource address at a time.
